# 阶段4-第四次-3D模型与剖切交互问题诊断与修复方案

## Objectives (目标)

针对 `tunnel-drainage-platform/frontend/src/components/three/Viewer3D.vue` 及其关联模块（`TunnelGenerator.ts`、`Reinforcement.ts`、`Environment.ts`、`PostProcessing.ts`、`lining.vert`、`lining.frag`）在 3D 模型渲染、剖切分析交互、图层显隐及最不利探针表达中发现的 4 项关键工程问题，进行深层根因诊断，并给出确定性的代码修复与重构方案：

1. **构件精简**：彻底去除“超前小导管”冗余构件及对应管网渲染逻辑，简化加固层拓扑；
2. **剖切修复**：彻底修复开启【3D 剖切分析】时【隧道衬砌】图层全局消失的 Shader 缺陷，并实现【水文环境】图层（水位面、地面、地下水粒子、动水流线）随剖切平面的动态实时剔除；
3. **图层细化**：在【图层显隐控制】面板中为【水文环境】增加独立的“地下水粒子特效”二级开关按钮；
4. **探针精确定位**：纠正【最不利受力单元】悬浮看板与 3D 探针位置，将模糊的全局里程段（如 `DK0+000 ~ DK47+000`）重构为精确里程点标注（如 `DK0+025.0`），并将 3D 受力探针与云图环精准移动至对应的 DK 空间坐标。

---

## Constraints (约束条件)

1. **架构一致性**：不得破坏现有的 Vue3 Composition API + Three.js + Pinia (`snapshotStore`, `parameterStore`) 响应式数据流流转拓扑；
2. **WebGL 性能与显存**：保证 InstancedMesh 动态更新高效无卡顿，无高频 GC 垃圾回收，帧率维持在 60 FPS；
3. **Shader 规范**：符合 Three.js WebGL2/GLSL 3.00 ES 规范，剖切宏 `#include <clipping_planes_vertex>` 必须紧跟在空间坐标矩阵变换之后；
4. **输出完整性**：所有修改方案需给出确定性代码实现，禁止出现 TODO、伪代码或未验证占位符。

## Architecture (诊断与架构解构)

### 1. 超前小导管去除诊断 (`Reinforcement.ts` / `Viewer3D.vue`)
- **根因分析**：`ReinforcementManager` 中保留了 `advancePipeMesh`（`InstancedMesh`）及 `updateAdvancePipes()` 逻辑，在 `Viewer3D.vue` 中挂载于场景，不仅增加了无用几何体绘制开销，且与实际工程加固设计需求不符。
- **架构调整**：清理 `ReinforcementManager` 中的 `advancePipeMesh` 成员、顶点缓存及更新函数，`getMeshes()` 仅返回 `groutingMesh` 与 `criticalGroutingMesh`。

### 2. 3D 剖切分析失效与水文随动诊断 (`lining.vert` / `Environment.ts` / `Viewer3D.vue`)
- **根因分析 A（衬砌开剖切后全部消失）**：
  在 `lining.vert` 中，`#include <clipping_planes_vertex>` 在第 22 行被调用，而 `vec4 mvPosition = viewMatrix * worldPosition;` 位于第 42 行。Three.js 内置剖切宏依赖 `mvPosition` 计算顶点到剖切平面的符号距离 `vClipPosition`。由于调用顺序倒置，`mvPosition` 在第 22 行尚未声明/赋值，导致 `vClipPosition` 恒为 0 或垃圾值，片元着色器执行 `clipping_planes_fragment` 时全部判定为被剖切并被 `discard` 丢弃。
- **根因分析 B（水文环境不随剖切改变）**：
  `Viewer3D.vue` 中的 `applyClippingPlanes()` 仅遍历了 `activeMeshes`，而 `envInstance` 包含的 `waterPlane`、`groundPlane`、`waterParticles`、`flowLines` 未被加入 `activeMeshes`。同时 `Environment.ts` 内的自定义 `ShaderMaterial` 缺少 Three.js 剖切宏声明与 `clipping: true` 配置。
- **架构调整**：
  - 将 `lining.vert` 中的 `#include <clipping_planes_vertex>` 调整至 `mvPosition` 计算完成之后；
  - 为 `Environment.ts` 内的材质开启 `clipping: true`，并在其顶点/片元 Shader 中注入 Three.js 标准剖切宏；
  - 为 `Environment` 类增加 `getMeshes()` 接口，统一注入 `Viewer3D.vue` 的 `activeMeshes` 及 `applyClippingPlanes()` 遍历队列。

### 3. 地下水粒子特效独立控制诊断 (`Viewer3D.vue`)
- **根因分析**：`layerVisibility` 响应式对象仅有主开关 `environment: true`，控制了水文环境所有 Mesh 的统一显隐。
- **架构调整**：
  在 `layerVisibility` 中扩展 `waterParticles: true`，并在 UI 图层控制面板中新增子级复选框。`updateLayerVisibility()` 时，粒子显隐由 `layerVisibility.environment && layerVisibility.waterParticles` 共同决定。

### 4. 最不利探针精准里程与空间定位诊断 (`PostProcessing.ts` / `Viewer3D.vue`)
- **根因分析**：
  在 `PostProcessing.ts` 中，`chainageText` 拼接逻辑硬编码为 `DK${startChain}~DK${endChain}`（即 `DK0+000 ~ DK47+000`），且受力环与 3D 探针的纵向 Z 坐标硬编码在隧道中央 `zPos = -startChain - L / 2`，无法精准反映控制截面的真实 DK 里程点。
- **架构调整**：
  根据快照或计算参数提取精确控制里程偏移 `controlChainageOffset`（默认 `startChain + L/2` 或快照中的 `control_chainage`），将其格式化为标准的 `DK0+025.0` 格式，并以 `-controlChainageOffset` 作为 Z 轴世界坐标定位 3D 受力云图环、变截面多边形及最不利探针。

### 1. `Reinforcement.ts` 修改方案

```typescript
// frontend/src/components/three/Reinforcement.ts
import * as THREE from 'three';
import { buildHorseshoeShape } from './TunnelGenerator';

export interface GroutingConfig {
  rg: number;
  r2: number;
  rg_crit?: number;
  tg_crit?: number;
  start_chainage: number;
  end_chainage: number;
  tunnel_type: 'single' | 'double';
  D_spacing?: number;
}

export class ReinforcementManager {
  public groutingMesh: THREE.InstancedMesh;
  public criticalGroutingMesh?: THREE.InstancedMesh;
  private readonly nMaxGrouting: number;

  constructor(groutingConfig: GroutingConfig) {
    const L_grouting = groutingConfig.end_chainage - groutingConfig.start_chainage;
    const segmentsGrouting = Math.max(1, Math.ceil(L_grouting / 5.0));
    this.nMaxGrouting = segmentsGrouting * 2;

    const r_base = groutingConfig.r2 ? groutingConfig.r2 / 1.18 : 5.5;
    const shapeInitial = buildHorseshoeShape(r_base, groutingConfig.rg || (groutingConfig.r2 + 1.5), groutingConfig.r2 || 6.5, 0, 0.7);
    const groutingGeom = new THREE.ExtrudeGeometry(shapeInitial, { depth: 1.0, bevelEnabled: false, curveSegments: 32 });

    const groutingMaterial = new THREE.MeshStandardMaterial({
      color: 0x00ffff,
      roughness: 0.3,
      metalness: 0.1,
      transparent: true,
      opacity: 0.25,
      side: THREE.DoubleSide
    });
    this.groutingMesh = new THREE.InstancedMesh(groutingGeom, groutingMaterial, this.nMaxGrouting);
    this.groutingMesh.frustumCulled = false;
    this.groutingMesh.instanceMatrix.setUsage(THREE.DynamicDrawUsage);
    this.groutingMesh.count = 0;

    const criticalMaterial = new THREE.MeshStandardMaterial({
      color: 0xff6600,
      roughness: 0.3,
      metalness: 0.1,
      transparent: true,
      opacity: 0.35,
      side: THREE.DoubleSide
    });
    this.criticalGroutingMesh = new THREE.InstancedMesh(groutingGeom.clone(), criticalMaterial, this.nMaxGrouting);
    this.criticalGroutingMesh.frustumCulled = false;
    this.criticalGroutingMesh.instanceMatrix.setUsage(THREE.DynamicDrawUsage);
    this.criticalGroutingMesh.count = 0;
  }

  public updateGroutingFromSnapshot(config: GroutingConfig): void {
    const length = config.end_chainage - config.start_chainage;
    const segments = Math.max(1, Math.ceil(length / 5.0));
    const segmentLength = length / segments;

    const tg_original = Math.max(0, config.rg - config.r2);
    this.updateGroutingRing(
      this.groutingMesh,
      segments,
      segmentLength,
      config.start_chainage,
      config.r2,
      config.rg,
      tg_original > 0 ? 0x00ffff : 0x888888,
      0.25,
      config.tunnel_type,
      config.D_spacing
    );

    if (this.criticalGroutingMesh && config.rg_crit !== undefined && config.tg_crit !== undefined) {
      const hasCritical = config.tg_crit > 0;
      this.updateGroutingRing(
        this.criticalGroutingMesh,
        segments,
        segmentLength,
        config.start_chainage,
        config.r2,
        hasCritical ? config.rg_crit : config.r2,
        hasCritical ? 0xff6600 : 0x888888,
        hasCritical ? 0.35 : 0.1,
        config.tunnel_type,
        config.D_spacing
      );
    }
  }

  private updateGroutingRing(
    mesh: THREE.InstancedMesh,
    segments: number,
    segmentLength: number,
    _startZ: number,
    rInner: number,
    rOuter: number,
    _color: number,
    opacity: number = 0.25,
    tunnelType: 'single' | 'double' = 'single',
    D_spacing: number = 30.0
  ): void {
    const isDouble = tunnelType === 'double';
    const totalInstances = isDouble ? segments * 2 : segments;
    mesh.count = Math.min(totalInstances, mesh.instanceMatrix.count);

    if (rOuter > rInner) {
      const r_base = rInner ? rInner / 1.18 : 5.5;
      const horseshoeShape = buildHorseshoeShape(r_base, rOuter, rInner, 0, 0.7);
      const newGeom = new THREE.ExtrudeGeometry(horseshoeShape, { depth: 1.0, bevelEnabled: false, curveSegments: 32 });
      if (mesh.geometry) mesh.geometry.dispose();
      mesh.geometry = newGeom;
    }

    const matrix = new THREE.Matrix4();
    const position = new THREE.Vector3();
    const scale = new THREE.Vector3(1, 1, segmentLength);
    const quaternion = new THREE.Quaternion().setFromEuler(new THREE.Euler(0, 0, 0));

    let idx = 0;
    for (let i = 0; i < segments; i++) {
      const z = -(i * segmentLength + segmentLength / 2);
      const xOffsets = isDouble ? [-D_spacing / 2, D_spacing / 2] : [0];

      for (const xOff of xOffsets) {
        if (idx >= mesh.count) break;
        position.set(xOff, 0, z);
        matrix.compose(position, quaternion, scale);
        mesh.setMatrixAt(idx, matrix);
        idx++;
      }
    }
    mesh.instanceMatrix.needsUpdate = true;
  }

  public updateFromSnapshot(snapshot: any): void {
    if (!snapshot) return;
    const params = snapshot.input_parameter ?? snapshot.params ?? {};
    const critical = snapshot.critical_state ?? {};

    const groutingConfig: GroutingConfig = {
      rg: params.rg ?? snapshot.rg ?? 8.0,
      r2: params.r2 ?? snapshot.r2 ?? 6.5,
      rg_crit: critical.rg_crit,
      tg_crit: critical.tg_crit,
      start_chainage: params.start_chainage ?? snapshot.start_chainage ?? 0,
      end_chainage: params.end_chainage ?? snapshot.end_chainage ?? 50,
      tunnel_type: params.tunnel_type ?? snapshot.tunnel_type ?? 'single',
      D_spacing: params.D_spacing ?? snapshot.D_spacing
    };
    this.updateGroutingFromSnapshot(groutingConfig);
  }

  public getMeshes(): THREE.InstancedMesh[] {
    const meshes: THREE.InstancedMesh[] = [this.groutingMesh];
    if (this.criticalGroutingMesh) meshes.push(this.criticalGroutingMesh);
    return meshes;
  }

  public dispose(): void {
    this.groutingMesh.geometry.dispose();
    (this.groutingMesh.material as THREE.Material).dispose();
    if (this.criticalGroutingMesh) {
      this.criticalGroutingMesh.geometry.dispose();
      (this.criticalGroutingMesh.material as THREE.Material).dispose();
    }
  }
}
```

### 2. `lining.vert` 修改方案

在 `lining.vert` 中，将 `#include <clipping_planes_vertex>` 从开头移至 `mvPosition` 赋值完成后：

```glsl
// frontend/src/assets/shaders/lining.vert
#include <common>
#include <clipping_planes_pars_vertex>

uniform float r;
uniform float r1;
uniform float r2;
uniform float rg;

out vec3 vLocalPosition;
out vec3 vNormal;
out vec3 vViewPosition;
out vec3 vInstanceColor;
out vec3 vLocalNormal;
out vec3 vWorldPosition;

#include <logdepthbuf_pars_vertex>

void main() {
    vLocalPosition = position;
    vLocalNormal = normal;
    
    vec4 localPosition = vec4(position, 1.0);
    vec3 transformedNormal = normal;
    
    #ifdef USE_INSTANCING
        localPosition = instanceMatrix * localPosition;
        mat3 instanceNormalMatrix = mat3(instanceMatrix);
        transformedNormal = instanceNormalMatrix * transformedNormal;
    #endif
    
    vec4 worldPosition = modelMatrix * localPosition;
    vWorldPosition = worldPosition.xyz;

    vNormal = normalize(normalMatrix * transformedNormal);
    vec4 mvPosition = viewMatrix * worldPosition;
    vViewPosition = -mvPosition.xyz;

    // 【关键修复】：必须在 vec4 mvPosition 计算完成之后调用剖切顶点宏
    #include <clipping_planes_vertex>
    
    #ifdef USE_INSTANCING_COLOR
        vInstanceColor = instanceColor;
    #else
        vInstanceColor = vec3(1.0);
    #endif
    
    gl_Position = projectionMatrix * mvPosition;
    #include <logdepthbuf_vertex>
}
```

## Acceptance Criteria (验收标准)

1. **构件剔除验证**：
   - 3D 视图中不再渲染任何超前小导管几何体，控制台无相关未定义报错。
2. **剖切分析验证**：
   - 打开【3D 剖切分析】后，滑动位置 Slider（如 0m ~ 50m），【隧道衬砌】正常被剖切并清晰展示马蹄形断面切面，不再整体消失；
   - 切换 X / Y / Z 剖切轴，【水文环境】（水位面、地形面、水流线、水流粒子）同步被实时剖切剔除。
3. **粒子开关验证**：
   - 取消勾选【└ 地下水粒子特效】，场景中地下水蓝光粒子独立隐藏，水文环境其余组件（水位面、地表）保持可见。
4. **探针位置与看板验证**：
   - 悬浮看板顶部标题准确显示为 `最不利受力单元 #0 (DK0+025.0)`（或对应的精准 DK 坐标）；
   - 3D 场景中的受力云图环、弯矩/轴力包络网格及最不利探针精确定位在 `z = -25.0m` 对应的 DK 里程位置。
