## 一、 构建拓扑与交付形态概述 (Build Topology & Modes)

本项目支持两种截然不同但业务计算内核（水动力-力学双分支计算、3D 数字孪生渲染、Typst 纯矢量科技排版、A3 数字化施工蓝图直出）100% 同构复用的物理交付形态：

```
+─────────────────────────────────────────────────────────────────────────────────────────────────+
|                       隧道工程多维协同智能排水自适应平台 - 本地手动编译与构建拓扑                         |
+─────────────────────────────────────────────────────────────────────────────────────────────────+

 【模式 A：桌面独立 GUI 客户端 (Desktop Standalone)】
   构建载体: Windows 11 本地开发宿主机
   编译链条: Python 3.11 (PyInstaller) ──> Rust Stable (Tauri 2.0 CLI) ──> WiX 3.11 / NSIS

   构建载体: Windows 11 本地主控 + 局域网 iMac 26 构建工作站 (SSH 直连 192.168.120.11)

     1. 云端镜像: reaticle/tunnel-drainage-frontend:v1.0.0 (及 latest)
     2. 云端镜像: reaticle/tunnel-drainage-backend:v1.0.0 (及 latest)
     3. 独立部署物料: dist-docker/ (含 .env.production, docker-compose.yml, nginx/nginx.conf)
```

## 二、 编译前置环境基准核验 (Prerequisites & Baselines)

| **C++ 构建工具** | Visual Studio 2022 C++ Build Tools | `cl.exe` (在 VS 开发人员命令行中可查) | 提供 Windows MSVC 静态链接库与 SDK |

## 三、 本地编译安全门禁与密码规程 (Security & Auth Gate)

依据《阶段6-专题-交付体系安全认证与密码生命周期配置架构方案》，本地手动编译必须严格执行以下安全隔离与密码固化规则：

### 3.1 物理隔离与 Git 防泄露红线
- **绝对黑名单**：
  1. `tunnel-drainage-platform/backend/app/core/_build_constants.py`（临时编译常量，打包后必须物理擦除）；
  2. `tunnel-drainage-platform/dist-docker/.env.production` 或 `tunnel-drainage-platform/deploy/server/.env.production`（生产部署敏感环境配置，严禁入库）；
  3. `release/` 与 `dist-docker/` 构建产物目录。
- **构建前置断言**：编译流水线自动扫描 `git status --porcelain`，一旦检测到上述文件未被 `.gitignore` 保护或已被 Git 跟踪，将物理阻断构建，退出码设为 `1`。

### 3.2 密码参数化与注入机制
- **桌面模式**：通过脚本参数 `-OperatorPassword "<定制口令>"`（或交互式输入）指定。口令在编译期通过 AST 字节码固化进 `tunnel-backend-sidecar.exe` 二进制，出厂不可在线修改，脱机运行全量核验敏感操作。默认口令为 `chongqing123456`。
- **服务器模式**：生产 Docker 镜像保持中立无密码固化；定制口令与系统生成的 32 字节高熵 HMAC 密钥仅写入独立分发的 `dist-docker/.env.production`。

## 四、 模式 A：桌面独立 GUI 模式本地编译操作规程

### 4.1 方式一：PowerShell 自动化一键打包 (推荐生产使用)

项目根目录已配备完整的工业级一键编译流水线脚本 `deploy/scripts/build-desktop.ps1`，该脚本严格保证临时编译文件的生命周期清理与多目标产物归集。

#### 步骤 1：打开终端并定位目录
使用管理员或标准权限启动 Windows PowerShell（推荐使用 Windows Terminal 或 PowerShell 7）：
```powershell
# relative/path: tunnel-drainage-platform/deploy/scripts/build-desktop.ps1
cd "d:\offices\Github\隧道工程多维协同智能排水自适应平台\tunnel-drainage-platform"
```

#### 步骤 2：执行一键编译构建与版本指定

脚本内置了版本单一真实源（SSOT）智能对齐与灵活的构建场景支持：

- **场景 A：交互式指定口令（使用工程当前配置版本）**
  ```powershell
  # 运行构建脚本，系统将交互提示输入固化操作口令（回车默认: chongqing123456），版本自动读取当前工程配置
  powershell -ExecutionPolicy Bypass -File deploy\scripts\build-desktop.ps1
  ```

- **场景 B：参数化静默指定定制密码（使用工程当前配置版本）**
  ```powershell
  # 通过参数直接注入出厂专属密码，非交互执行
  powershell -ExecutionPolicy Bypass -File deploy\scripts\build-desktop.ps1 -OperatorPassword "Tunnel2026CustomKey" -NonInteractive
  ```

- **场景 C：显式指定发布版本号（推荐发版使用）**
  ```powershell
  # 通过 -Version 参数显式指定版本（支持 "v1.2.0" 或 "1.2.0" 格式）
  # 脚本将自动对齐 tauri.conf.json、package.json 与 Cargo.toml，并按指定版本归集交付包
  powershell -ExecutionPolicy Bypass -File deploy\scripts\build-desktop.ps1 -Version "v1.2.0"
  ```

- **场景 D：全参数非交互自动化流水线构建（定制密码 + 指定版本）**
  ```powershell
  # 生产环境一键发布：同时指定固化口令与发行版本，零人工交互
  powershell -ExecutionPolicy Bypass -File deploy\scripts\build-desktop.ps1 -OperatorPassword "Tunnel2026CustomKey" -Version "v1.2.0" -NonInteractive
  ```

> [!NOTE]
> **版本号指定与生效机制说明（SSOT 规范）：**
> 1. **命令行参数优先（动态同步）**：当传入 `-Version` 参数时，脚本会自动规范化版本字符串（去除前导 `v`），并自动同步更新 `frontend/src-tauri/tauri.conf.json`、`frontend/package.json` 及 `frontend/src-tauri/Cargo.toml`，确保三处源码定义与最终二进制元数据完全一致。
> 2. **源码持久化驱动（默认回退）**：若未显式传入 `-Version` 参数，脚本将以 [tauri.conf.json](file:///d:/offices/Github/隧道工程多维协同智能排水自适应平台/tunnel-drainage-platform/frontend/src-tauri/tauri.conf.json) 中的 `"version"` 字段作为基准版本执行编译。
> 3. **交付产物命名规范**：最终发布的交付物将严格遵循 `TunnelDrainagePlatform-v<Version>-x64-<Format>` 格式自动归集至 `release/desktop/`：
>    - 安装向导：`TunnelDrainagePlatform-v<Version>-x64-Setup.exe`
>    - MSI 安装包：`TunnelDrainagePlatform-v<Version>-x64.msi`
>    - 绿色便携包：`TunnelDrainagePlatform-v<Version>-x64-Portable.zip`

#### 步骤 3：验收流水线自动化执行日志
流水线将依次自动执行以下 5 大阶段并给出彩色状态指示：
1. `[Step 1/5]` 动态写入 `_build_constants.py`，调用 `pyinstaller packaging/sidecar.spec` 冻结生成 `tunnel-backend-sidecar.exe`，并在 `finally` 块中彻底销毁临时源码；
2. `[Step 2/5]` 将后端编译产物同步复制到 `frontend/src-tauri/binaries/` 下的双规格目标文件；
3. `[Step 3/5]` 切换至 `frontend/` 目录执行 `npm run build`，编译 Vite 6 生产静态单页应用；
4. `[Step 4/5]` 调用 `npx tauri build`，调度 Rust MSVC 编译器链接 Win32 Job Object 守护模块并打包 NSIS 与 MSI 安装向导；
5. `[Step 5/5]` 提取编译后的免安装便携版可执行程序，压缩生成 Portable ZIP 包，归集全量产物至 `release/desktop/` 并计算 SHA-256 哈希值写入 `SHA256SUMS.txt`。

若自动化脚本执行报错，或需要对特定子模块（如仅调试后端 Sidecar 或前端 Tauri 窗口）进行修改验证，请按照以下标准化分步指令执行：

#### 步骤 8：组装绿色便携版 (Portable) 与哈希归集
```powershell

Remove-Item $PortableTempDir -Recurse -Force
Write-Host "[OK] 绿色便携包组装完成: $PortableZip" -ForegroundColor Green

# 3. 计算 SHA-256 完整性哈希清单
$hashList = @()
Get-ChildItem -Path $DesktopReleaseDir -File | Where-Object { $_.Name -ne "SHA256SUMS.txt" } | ForEach-Object {
    $hash = (Get-FileHash -Path $_.FullName -Algorithm SHA256).Hash.ToLower()
    $hashList += "$hash  $($_.Name)"
}
Set-Content -Path "$DesktopReleaseDir\SHA256SUMS.txt" -Value $hashList -Encoding UTF8 -Force
Write-Host "[OK] SHA-256 校验和已输出至 $DesktopReleaseDir\SHA256SUMS.txt" -ForegroundColor Green
```

## 七、 常见编译故障诊断与自愈手册 (Troubleshooting)

### 故障 1：PyInstaller 打包报错 `ModuleNotFoundError: No module named 'typst'` 或缺少依赖
- **现象**：执行 `pyinstaller packaging/sidecar.spec` 时提示找不到某些子模块，或打包后的 exe 运行时报错 `No module named 'aiosqlite'`。
- **根本原因**：PyInstaller 静态代码分析未能捕获动态导入（Dynamic Import）的隐式依赖。
- **解决方案**：
  1. 检查 `tunnel-drainage-platform/backend/packaging/sidecar.spec`；
  2. 确保在 `hiddenimports` 列表中包含缺失的模块名，例如：
     ```python
     # relative/path: tunnel-drainage-platform/backend/packaging/sidecar.spec
     hiddenimports = [
         "uvicorn", "uvicorn.logging", "uvicorn.protocols.http.auto",
         "aiosqlite", "sqlalchemy.dialects.sqlite.aiosqlite",
         "typst", "typst._typst", "pydantic", "pydantic_settings"
     ]
     ```
  3. 重新执行打包并确认虚拟环境中已安装相应包。

---

###故障 2：Tauri build 报错 `externalBin not found: tunnel-backend-sidecar-x86_64-pc-windows-msvc.exe`
- **现象**：执行 `npx tauri build` 时 Rust 报错，提示未找到 external binary。
- **根本原因**：Tauri 2.0 在编译带有 `externalBin` 的应用时，会严格检测 Target Triple 命名规范。在 Windows MSVC 编译环境下，必须存在以 `-x86_64-pc-windows-msvc.exe` 为后缀的二进制文件。
- **解决方案**：
  在 `frontend/src-tauri/binaries/` 目录下同时放置以下两个命名拷贝：
  - `tunnel-backend-sidecar.exe`
  - `tunnel-backend-sidecar-x86_64-pc-windows-msvc.exe`
  （`build-desktop.ps1` 脚本已内建此双重同步机制）。

---

### 故障 3：WiX Toolset 未找到导致 MSI 打包跳过或失败
- **现象**：`tauri build` 完成了可执行文件编译，但提示未能生成 `.msi` 安装包。
- **根本原因**：宿主机未安装 WiX Toolset v3.11 或环境变量 `PATH` 未配置。
- **解决方案**：
  1. 从 WiX 官方仓库下载安装 WiX Toolset v3.11；
  2. 将 `C:\Program Files (x86)\WiX Toolset v3.11\bin` 添加至系统环境变量 `PATH`；
  3. 若仅需轻量分发，可直接使用流水线生成的 NSIS 安装向导（`.exe`）或绿色便携包（`.zip`），两者功能 100% 等价。

---

### 故障 4：SSH 连接 iMac 26 出现 `Permission denied (publickey)` 或超时
- **现象**：执行 `deploy-docker.ps1` 时提示 `无法通过 SSH 连接到 iMac 构建机`。
- **根本原因**：局域网 IP 发生漂移、iMac 处于睡眠状态，或 Windows 本地未配置 SSH 公钥互信。
- **解决方案**：
  1. 在 iMac 26 系统设置 -> 通用 -> 共享中，确保“远程登录 (Remote Login)”处于开启状态，并勾选允许用户 `reaticle` 访问；
  2. 在 Windows PowerShell 生成公钥（`ssh-keygen -t ed25519`），并通过以下命令将公钥分发至 iMac：
     ```powershell
     type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh reaticle@192.168.120.11 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
     ```
  3. 执行 `ssh reaticle@192.168.120.11` 验证免密码登录。

---

### 故障 5：Docker Buildx 交叉编译提示 `exec format error` 或 QEMU 缺失
- **现象**：在 iMac 26 上使用 Buildx 编译 `linux/amd64` 镜像时构建器异常终止。
- **根本原因**：macOS Apple Silicon (M系列芯片) 运行在 ARM64 架构下，编译 AMD64 镜像依赖 QEMU 仿真器或 Rosetta 虚拟化支持；若构建器状态损坏则无法完成指令集转换。
- **解决方案**：
  在 iMac 终端重置并新建容器化构建器实例：
  ```bash
  # 删除陈旧损坏的构建器
  docker buildx rm tunnel-builder 2>/dev/null || true
  # 重新创建支持多架构容器驱动的构建器并引导激活
  docker buildx create --name tunnel-builder --driver docker-container --bootstrap --use
  # 验证当前支持的平台清单
  docker buildx inspect tunnel-builder
  # 输出应包含: Platforms: linux/arm64, linux/amd64
  ```
